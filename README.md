# فایل‌های Saved Messages تلگرام — وب‌اپ محلی

وب‌اپی که روی کامپیوتر خودتان (ویندوز ۱۰) اجرا می‌شود و از طریق مرورگر
(دسکتاپ، موبایل، تبلت — در همان شبکه‌ی وای‌فای) قابل استفاده است.
فایل‌های Saved Messages را به‌صورت آیکون/پیش‌نمایش نشان می‌دهد، هر بار
۵۰ تا با دکمه‌ی بعدی/قبلی، و امکان دانلود و حذف با راست‌کلیک یا لمس طولانی.

## پیش‌نیازها

1. **Node.js نسخه ۱۸ به بالا** — از https://nodejs.org دانلود و نصب کنید.
2. **api_id و api_hash** تلگرام — از https://my.telegram.org (شما این را دارید).

## نصب

```bash
cd telegram_saved_web
npm install
```

## تنظیمات (config.json)

اولین بار که برنامه را اجرا کنید، فایل `config.json` به‌صورت خودکار در
کنار همین پوشه ساخته می‌شود. آن را باز کنید و مقادیر زیر را پر کنید:

```json
{
  "apiId": 1234567,
  "apiHash": "abcdef1234567890abcdef1234567890",
  "phone": "+989123456789",
  "proxyMode": "auto"
}
```

### تنظیم پروکسی (v2ray / Proxifier)

سه حالت برای `proxyMode` وجود دارد:

| مقدار | رفتار |
|---|---|
| `"auto"` (پیشنهادی) | ابتدا اتصال مستقیم را امتحان می‌کند؛ اگر طی چند ثانیه موفق نشد (که در ایران معمولاً همینطور است)، خودکار به SOCKS5 زیر سوییچ می‌کند. اگر Proxifier را طوری تنظیم کرده باشید که ترافیک `node.exe` را بگیرد و از طریق v2ray تانل کند، همین حالت هم به‌خوبی کار می‌کند، چون از دید برنامه اتصال «مستقیم» به نظر می‌رسد ولی واقعاً توسط Proxifier مسیردهی می‌شود. |
| `"direct"` | همیشه بدون دخالت این برنامه در پروکسی — برای زمانی که Proxifier به‌طور شفاف کل ترافیک را می‌گیرد. |
| `"proxy"` | همیشه مستقیماً به پورت SOCKS5 محلی v2ray وصل می‌شود (بدون نیاز به Proxifier). |

اگر می‌خواهید حالت `"proxy"` را استفاده کنید، پورت SOCKS5 داخلی v2ray
خودتان را در `config.json` تنظیم کنید (این پورت را در تنظیمات
inbound v2ray‌تان — معمولاً چیزی شبیه ۱۰۸۰۸ یا ۱۰۸۰ — پیدا می‌کنید):

```json
"proxy": {
  "ip": "127.0.0.1",
  "port": 10808,
  "socksType": 5
}
```

## اجرا

```bash
npm start
```

سپس در مرورگر باز کنید: **http://127.0.0.1:4173**

### دسترسی از موبایل/تبلت

چون سرور فقط روی `127.0.0.1` (خودِ همین کامپیوتر) گوش می‌دهد، برای
دسترسی از گوشی/تبلت در همان وای‌فای باید:

1. در `server/index.js` مقدار `"127.0.0.1"` در خط `app.listen` را به `"0.0.0.0"` تغییر دهید (تا روی همه‌ی رابط‌های شبکه گوش بدهد).
2. آی‌پی محلی کامپیوترتان را در ویندوز با دستور `ipconfig` پیدا کنید (چیزی شبیه `192.168.1.x`).
3. در مرورگر گوشی/تبلت به آدرس `http://192.168.1.x:4173` بروید.
4. اگر Windows Firewall درخواست اجازه نشان داد، دسترسی را برای شبکه‌ی خصوصی تایید کنید.

**نکته امنیتی:** با این کار هر کسی در همان وای‌فای می‌تواند به Saved
Messages شما دسترسی داشته باشد. برای یک ابزار شخصی روی وای‌فای خانگی
معمولاً مشکلی ندارد، ولی روی شبکه‌های عمومی/مشترک این کار را نکنید.

## معماری پروژه

```
server/
  index.js            نقطه ورود Express + تمام API endpoint ها
  config.js            خواندن/نوشتن config.json
  sessionStore.js       ذخیره StringSession تلگرام (session.txt)
  telegramService.js    تنها فایلی که مستقیم با GramJS کار می‌کند
public/
  index.html
  css/styles.css        تم روز/شب + طراحی واکنش‌گرا
  js/theme.js            سوییچ تم
  js/api.js               fetch wrapper برای تماس با سرور
  js/app.js                صفحه‌بندی، گرید، پیش‌نمایش، منوی راست‌کلیک/لمس
```

هر تغییر در نحوه‌ی ارتباط با تلگرام فقط در `telegramService.js` اعمال
می‌شود؛ بقیه‌ی برنامه با آن کاری ندارد (معماری ماژولار مطابق بحث قبلی).

## محدودیت‌های نسخه فعلی (برای توسعه‌ی بعدی)

- دانلود/پیش‌نمایش فایل‌های خیلی حجیم (چند صد مگابایت به بالا) در حافظه
  بافر می‌شود، نه streaming تکه‌تکه — برای فایل‌های معمولی مشکلی ندارد.
- کش فقط در حافظه‌ی مرورگر (برای همان نشست) نگه داشته می‌شود، نه روی دیسک.
